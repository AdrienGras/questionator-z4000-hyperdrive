# F18 — Coloration de tous les langages — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tout bloc dont le langage est connu de Shiki est coloré (hors ligne compris), seule sa grammaire est chargée, et un langage inconnu donne du texte brut plus un avertissement non bloquant à la création de session.

**Architecture:** La normalisation et les pseudo-langages vivent dans `lib/markdown/languages.ts` (sans Shiki), partagés par le highlighter, `CodeBlock` et le domaine. Le domaine reconnaît les langages sur le catalogue `shiki/langs` (import statique, chunk du validateur seulement) et lève `unknown_code_language`. Le highlighter charge le même catalogue par `import()` et une grammaire par identifiant canonique.

**Tech Stack:** shiki 4.4.3 (`shiki/core`, moteur JavaScript, `shiki/langs`), React 19, Vitest 5, Playwright, Vite 8 / Rolldown.

**Spec:** `docs/superpowers/specs/2026-09-26-f18-langages-design.md` (D63). Le lire avant chaque tâche.

## Global Constraints

- Arborescence D59 (`docs/CONVENTIONS.md` § « Arborescence et imports », lignes 14-54) : sens `lib` ← `domain` ← `components` ← `features` ; `lib/` n'importe jamais `domain/` ; imports `@/…`, pas de barrel, kebab-case, tests colocalisés.
- Un seul catalogue : `bundledLanguages` de `shiki/langs` (346 clés, identifiants et alias). Pas de liste statique, pas d'`import.meta.glob`.
- Pseudo-langages : `text`, `txt`, `plain`, `plaintext` — texte brut, aucun chargement (ni catalogue, ni grammaire), aucun avertissement.
- Normalisation : premier mot de l'info string, en minuscules (`PHP title=x` → `php`).
- Jamais d'import de `@shikijs/*` (non résoluble avec pnpm, QUIRKS) ; le highlighter n'importe aucune valeur statique de `shiki`.
- Thèmes `github-light` / `github-dark`, `defaultColor: false`, moteur JavaScript, aucun WASM.
- Code `unknown_code_language`, sévérité `warning`, params `{ language: string; questionId: string }`, chemin `['categories', c, 'questions', q, 'prompt' | 'answer']`, une issue par couple (question, langage), à la première occurrence.
- Messages : fr « Le langage « {language} » d'un bloc de code de la question {questionId} n'est pas reconnu : il s'affichera en texte brut. » ; en « The language “{language}” of a code block in question {questionId} is not recognized: it will be shown as plain text. »
- L'accueil ne charge ni le catalogue ni aucune grammaire.
- Commits gitmoji en français, présent, emoji Unicode, terminés par `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` et `Claude-Session: https://claude.ai/code/session_01MuZBBR1c8YAVppDfkPmP1g`. `rtk pnpm check` vert à chaque tâche ; vitest via `rtk proxy pnpm vitest run <chemin>`.

## Review Focus

- Un alias et son identifiant (`py`/`python`, `yml`/`yaml`) ne chargent la grammaire qu'une fois, et le validateur accepte exactement ce que le rendu colore (Task 1 et Task 3, tests croisés sur les mêmes entrées).
- Un bloc imbriqué (```` ``` ```` dans un bloc `~~~`) ou indenté de 4 espaces ne lève pas d'avertissement fantôme (Task 1).
- Casse : ```` ```PHP ```` est coloré et n'avertit pas (Task 1, Task 3).
- Catalogue en échec réseau : texte brut, puis nouvel essai au montage suivant (Task 3).
- Une fuite de `shiki/langs` dans le bundle initial (import statique ajouté par erreur) doit faire rougir `check:bundle` (Task 4).
