# F11 — Écran final et ajustement — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remplacer `DoneState` par l'écran final de la vue examinateur : toutes les notes, le détail du passage, la popup d'ajustement (ouverte une fois en fin de passage, puis par « Ajuster »), la réinitialisation de l'étudiant et « Étudiant suivant ».

**Architecture:** Transitions pures `(session, input, deps?) → session` dans `src/domain/passage/`, qui lèvent une `PassageError` typée ; `usePassageActions` les passe à `updateSession` (transaction Dexie, session fraîche). L'ouverture automatique de la popup est déduite de la base (`done && finalRevealedAt === undefined`, D66), sans état local persisté.

**Tech Stack:** React 19, TanStack Router, Dexie (`updateSession`), Vitest + Testing Library + fake-indexeddb, Tailwind 4 + shadcn/base-ui (`dialog`, `alert-dialog`, `button`, `input`, `label`).

**Spec:** `docs/superpowers/specs/2026-09-29-f11-final-design.md` (décisions D65, D66 dans `docs/DECISIONS.md`).

## Global Constraints

- Arborescence D59 : `domain/` sans React, sans `lib/db/`, sans `lib/i18n/use-ui.ts` ; `features/session/` n'importe aucune autre feature ; imports `@/…` (`./…` même dossier seulement, jamais `../`) ; pas de barrel ; fichiers en kebab-case ; tests colocalisés. `pnpm deps` doit passer.
- Toute chaîne visible, `aria-label` compris, passe par `text(clé, params)` ; chaque nouvelle clé dans `UiMessageParams`, dans les dictionnaires `fr` **et** `en` de `src/lib/i18n/ui-messages.ts`, **et** dans l'objet `SAMPLE` de `src/lib/i18n/ui-messages.test.ts` (sinon `pnpm typecheck` échoue).
- Props `Readonly<{…}>` ; setter d'état nommé `setX` ; `useUi()` appelé une seule fois, dans `ExaminerView` ; les sous-composants reçoivent `ui: Ui`.
- Pas de ternaire imbriqué (Sonar S3358) : if/return ou fonction auxiliaire. Pas de `span tabIndex` (S6845). `waitForElementToBeRemoved` seulement avec `queryBy*` (S9153).
- Transitions : jamais de mutation de l'entrée ; chaque test de refus fait `structuredClone(session)` avant et `expect(session).toEqual(snapshot)` après (oxlint `expect-expect` ne compte pas `expectPassageError`). Helper `expectPassageError(fn, code)` de `@/testing/passage-assertions`.
- Dépendances de temps injectées et appelées **dans** le mutator, de façon synchrone (`now: () => Date`).
- Dialogues : squelette CONVENTIONS « Dialogue de saisie » (formulaire dans un enfant démonté à la fermeture ; `onSave` renvoie une promesse ; échec → `write_error` en `role="alert"`, dialogue ouvert). Référence : `src/components/text-field-dialog.tsx`, `src/features/home/components/delete-dialog.tsx`.
- Tests d'écran : `import 'fake-indexeddb/auto'` en première ligne, `beforeEach(() => db.sessions.clear())`, `putSession(...)` puis `renderAt('/session/session-1')` (`@/testing/render-at`) ; `makeConfig(scoring, absent?, skips?)` et `makeStudent(attempts, overrides)` de `@/testing/student-fixtures`. `minimalConfig` n'a qu'**une** question par catégorie : un test qui fabrique `attempt-2` fournit une catégorie à plusieurs questions (voir `src/features/session/skip.test.tsx`). Langue de test : `fr`.
- **Fixture de notation commune** (tests des Tasks 1, 2, 4, 5) : `makeConfig({ questionsPerStudent: 1, maxRawScore: 20, finalScale: 20, rounding: { mode: 'nearest', decimals: 2, step: 0.5 } })` — pas de 0,5, donc « 13,5 » formaté avec une décimale (le pas par défaut est 0,01 et afficherait « 13,50 »). `computeScores` ne contrôle pas le barème : `makeStudent([13.5])` donne une convertie de 13,5, `makeStudent([20])` 20/20, `makeStudent([0])` 0. Un test d'écran qui passe par les boutons « Noter » a besoin d'un barème contenant la valeur (catégorie propre au test).
- Motifs et justifications : `normalizeReason` (trim, 200 caractères max, vide → `undefined`) ; champ de saisie `maxLength={MAX_REASON_LENGTH}`.

## Review Focus

1. Double-clic sur « Enregistrer » ou « Annuler » de la popup de fin de passage : une seule écriture, aucun message d'erreur, popup fermée — Task 5, test dédié.
2. Réinitialiser un étudiant déjà révélé, le refaire passer : la popup de fin s'ouvre de nouveau à sa dernière note (`finalRevealedAt` a été vidé) — Task 5.
3. Pas d'arrondi autre que 0,5 (`rounding.step` 0,25 ; `decimals` 0) : boutons − / + d'un pas exact, « 0,3 » refusé avec un pas de 0,5, finale formatée au bon nombre de décimales — Task 2 (`parseAdjustmentInput`, `previewFinal`) et Task 5 (− / + avec un pas de 0,25).
4. Saisie « 1.5 » comme « 1,5 », « −1 » avec le signe moins typographique, espaces autour : tous acceptés — Task 2.
5. Dernier étudiant restant terminé pendant qu'un autre est absent : « Étudiant suivant » désactivé avec la mention, jamais de boucle sur l'étudiant courant — Task 2 (`nextStudent`) et Task 4 (écran).
