# F09 — Écran de passage — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remplacer le corps provisoire de la vue examinateur par l'écran de passage : grille, tirage sans biais, question markdown, réponse repliée, notation, états absent / terminé / sans étudiant, sélecteur d'étudiant provisoire.

**Architecture:** Transitions pures `(session, input, deps) → session` dans `src/domain/passage/`, qui lèvent une `PassageError` typée ; un hook de la feature `session` les passe à `updateSession` (transaction Dexie, session fraîche). L'écran lit la session par la liveQuery existante (`useSession`) et ne garde aucune copie locale.

**Tech Stack:** React 19, TanStack Router (hash, file-based), Dexie (`updateSession`), Vitest + Testing Library + fake-indexeddb, Tailwind 4 + shadcn (`tooltip`, `button`).

**Spec:** `docs/superpowers/specs/2026-09-27-f09-passage-design.md` (décision D64 dans `docs/DECISIONS.md`).

## Global Constraints

- Arborescence D59 : `domain/` sans React, sans `lib/db/`, sans `lib/i18n/use-ui.ts` ; `features/session/` n'importe aucune autre feature ; imports `@/…` (`./…` même dossier seulement, jamais `../`) ; pas de barrel ; fichiers en kebab-case ; tests colocalisés. `pnpm deps` doit passer.

- Mutator de `updateSession` synchrone, sans `await` étranger à Dexie ; jamais `db.sessions.*` hors `src/lib/db/` (sauf tests).
- Couleur de catégorie : `style={{ '--category-color': color }}`, en accent seulement (bordure, icône), jamais en fond sous du texte (D26).
- Tests d'écran : `import 'fake-indexeddb/auto'` en première ligne, `beforeEach(() => db.sessions.clear())`, `putSession(...)` puis `renderAt('/session/<id>')` (`@/testing/render-at`). Langue de test : `fr`.

### Task 3: Hook `usePassageActions`

**Files:**
- Create: `src/features/session/hooks/use-passage-actions.ts`
- Test: `src/features/session/hooks/use-passage-actions.test.ts`

**Interfaces:**
- Consumes: Task 2 (`drawQuestion`, `scoreAttempt`, `setActiveStudent`, `PassageError`) ; Task 1 (`cryptoRandomInt`) ; `updateSession` (`@/lib/db/sessions`).
- Produces:
  ```ts
  export type PassageActions = {
    draw: (categoryId: string) => Promise<void>
    score: (attemptId: string, value: number) => Promise<void>
    selectStudent: (studentId: string) => Promise<void>
    busy: boolean
    error: Error | null
  }
  export function usePassageActions(sessionId: string, studentId: string | undefined): PassageActions
  ```

- [ ] **Step 1: Écrire les tests qui échouent** (`renderHook` + `act`, `fake-indexeddb/auto` en tête, `putSession(makeSession(...))`, lecture par `getSession`)

- `draw('a')` écrit un attempt `pending` sur l'étudiant `studentId` ; `busy` repasse à `false`.
- `score(id, 1)` passe l'attempt en `scored`.
- `selectStudent('student-2')` change `activeStudentId`.
- concurrence en base : `await Promise.all([updateSession(id, s => drawQuestion(s, input, deps)), updateSession(id, s => drawQuestion(s, input, deps))].map(p => p.catch(e => e)))` → exactement un attempt en base, et un des résultats est une `PassageError` de code `pending_exists`.
- double appel du hook dans le même `act` (`void result.current.draw('a'); void result.current.draw('a')`) → un seul attempt **et** `error === null` (le second appel est ignoré par la garde `useRef`, il ne part pas en base).
- refus métier : `draw('a')` alors qu'un pending existe (posé par `putSession`) → `error` est une `PassageError` `pending_exists`, rien d'écrit.
- `studentId` indéfini : `draw` et `score` ne font rien.
- une action réussie après une erreur remet `error` à `null`.

- [ ] **Step 2: Lancer, vérifier l'échec**

Run: `rtk pnpm vitest run src/features/session/hooks`
Expected: FAIL.

- [ ] **Step 3: Implémenter**

Une fonction interne `run(mutator)` : si `inFlight.current` est vrai, retour immédiat ; sinon `inFlight.current = true`, `setBusy(true)`, `setError(null)`, `await updateSession(sessionId, mutator)` dans un `try/catch` qui fait `setError(e instanceof Error ? e : new Error(String(e)))`, `finally` remet la ref et `busy`. Deps de `draw` : `{ random: (n) => cryptoRandomInt(n), newId: () => crypto.randomUUID(), now: () => new Date() }`, passées telles quelles au mutator (appels synchrones dans la transaction).
